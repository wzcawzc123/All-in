# 供应商账号路由

每个供应商独立保存 `accountRouting`，默认 `rotate`，支持 `usage`（用量均衡）与 `pace`（到期优先）。三种策略用于新会话首次分配与必要的安全接替；已成功的账号池会话优先保持原账号。模型权限、启停、冷却、未知执行和重试安全边界继续生效。普通商业 API Key 的软亲和仍由高级设置显式控制。

## 本地122：会话内保持成功账号

- 首次A、B明确被限流/额度拒绝，C成功后，续聊与工具回传直接用C。C确认受限后才安全接替；替代账号成功后更新该会话绑定。
- 新会话按原策略分配；轮流游标跟随实际成功账号推进，旧会话续聊不会倒回游标。并发或慢首轮等待受原请求预算约束，普通本地排队不被误判为上游限流。
- 优先使用明确会话/线程标识，并隔离调用凭据、协议、请求模型和子线程。无标识时只用已成功交付回复的完整历史衔接；相同首句不会合并独立会话，确实歧义、历史被裁剪、内容不支持或超限时不猜。
- 历史索引只保留HMAC和不透明标识，不保存提示词、回复或凭据明文；输入/输出观察上限1 MiB UTF-8、512条历史消息，索引4096项、绑定1024项，成功续期最长30天。当前为进程内状态，重启和相关配置变化会重新分配，不承诺跨重启保持或厂商缓存命中。
- ETA可能在首轮最终交付前发送工具结果。完整工具参数写给客户端前登记暂定历史关联，后续等待原owner成功；失败取消清理，暂定关联不被当作成功绑定。
- WorkBuddy流式工具的后续包可能带空 `id/name`。观察器忽略空元数据，保留已收到的工具身份及原始参数增量；不改动实际工具业务内容。
- 只接受明确拒绝的安全接替，未知执行、部分业务输出、参数或协议错误不盲目跨账号重发。其他特殊供应商保留其原有独立冷却及不可重放规则。
- 无标识的WorkBuddy账本标记为 `history:` 派生会话引用；它是路由衔接证据，不是客户端提供的原始会话ID。

均衡并不承诺积分精确等额：有可信且新鲜的额度比例时按使用比例选择；否则按本机近期可信 Token 与在途负载选择。到期模式使用明确的积分作废或额度重置信息；未知、已过期、只表示凭据有效期的日期不能用作积分到期日期。

参考固定本地 Magpie `023a5637350bfc21020d486c7703fc2a23be366e` 的 provider/routing.go、routing/client.js；npm 参考目录不更新。已对45个本地 npm 包入口作定向扫描，主要进一步核对 WorkBuddy 0.2.34、Trae 0.2.34、Qoder 0.2.67、MiniMax 0.2.9、Raccoon 0.1.11、Loomy 0.1.5、Cline 0.1.15、CatPaw 0.2.2、Copilot 0.1.2、ZCode 0.1.61。这是额度/到期/计费路径对照，不是45个插件全部功能的逐行审计或真实账号验收。

WorkBuddy：汇总余额与积分包到期明细分开读取。积分包 DeductionEndTime、ExpiredTime、CycleEndTime 的解释对齐固定插件；日切片不能当作某个账号特有的即将作废奖励。不同币种、积分、Token、百分比不直接相加。Raccoon 的余额回退可能触发赠送，不能为路由自动调用有副作用的余额/领取入口。

实现：供应商详情中的「账号路由」展开后可直接选择三种模式，写入独立的 provider.accountRouting。使用供应商状态令牌和原子落盘，失败或冲突不显示保存成功；轮询和保存后保留展开状态。默认仍轮流，未配置者行为不变。已有账号的稳定ID、账号启停、逐账号模型目录、冷却、一次性凭据和重试安全边界继续生效。

额度数据新鲜期120秒，活跃候选每60秒最多排一次读取，最多2个工作线程、16个排队任务；关闭网关会停止读取。没有完整快照时所有候选统一用近期Token比较，避免将未知视为零。比例相差0.5个百分点以内的账号按本机近期Token和在途负载打散；本机负载在重启后归零，不承诺跨重启的严格积分等额。
